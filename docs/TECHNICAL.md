# 기술 문서

대상: *Star Fox 2* (Japan) (Classic Mini, Switch Online) — 1MB LoROM, Super FX (GSU-2), 헤더 타입 `0x15`.
주소 표기: 파일 오프셋은 `0x…`, CPU/GSU 주소는 `$뱅크:주소`. GSU 뱅크 `$00-$3F:8000-FFFF` = 파일 `뱅크*0x8000 + (주소-0x8000)`.

## 1. 대사

- 포인터 테이블 `0x2DA5` (216개, 16비트, 값-0x8000 = 파일 오프셋), 대사 영역 `0x1168-0x2DA4` (뱅크 0).
- 한 대사 = `[화자][표정] 본문 00`.
  화자: 00 폭스, 01 피피, 02 팔코, 03 슬리피, 04 페퍼 장군, 05 안돌프, 07 미유, 08 페이, 0A 울프, 0B 피그마, 0C 알지, 0D 레온.
- 본문 제어 코드는 `0x11`(x -1px, 버튼 아이콘 조합용)뿐. 탁점·반탁점은 별도 글자.
- 줄바꿈은 GSU가 공백 기준으로 자동 계산. 폭 `$70:00CA` — 맵 대화창 `0x7F`(GSU 코드 `0x58402` 부근), 전투 통신창 `0x70`(65816 `0x54FF7`). 대사 하나는 3줄 이내여야 함.

## 2. 폰트

폰트 헤더(원본은 뱅크 `$0D`: `E0F4`, `E1FB`(대사), `EE06`, `EED7`):

```
+0 행당 바이트 수(stride)   +1 높이(12)   +2 첫 코드(21)   +3 끝 코드(FE)
+4 자간(1)                  +5 u16 헤더→비트맵 오프셋
+7 코드→글리프 맵 (끝-첫+1 바이트, FF=없음)
   u16 글리프 항목: 하위 11비트 = 스트립 x, 상위 5비트 = 폭
   1bpp 가로 스트립 (높이 12, stride ≤ 255 → 최대 2040px)
```

1바이트 코드(최대 222자)와 스트립 폭 제한 때문에 한글(약 450자)이 한 페이지에 들어가지 않음 → 페이지 방식으로 확장.

## 3. 슈퍼FX 훅 (`tools/build_ko.py`, `tools/gsu_asm.py`)

롬 크기는 원본과 같은 1MB. 새 데이터는 원래 비어 있던 곳(뱅크 끝 0xFF 채움)과 쓰지 않게 된 곳에만 넣음 (`tools/freespace.py`).

- **폰트 페이지 0**: 원래 일본어 대사 폰트 자리 `$0D:E1FB`(다음 폰트 `EE06` 전까지 3083바이트). 대사 폰트 포인터는 그대로.
- **페이지 1~N**: 뱅크 끝 빈 공간에 큰 순서로 배치 (현재 `$03:F972`, `$02:FBE8`, `$0B:FBEF`, `$17:FD40`, `$10:FD81`, `$04:FDD6`).
- 대사 바이트 `0x01`~`0x0F` = 다음 바이트를 해당 페이지에서 찾음 (본문의 원래 제어 코드는 `0x11`뿐이라 충돌 없음).
- 훅 코드 `$01:FEC0` (원래 FF로 비어 있던 곳, 193바이트 + 페이지 표):
  - **페이지 표**: 페이지마다 `[헤더 주소 lo, hi, 뱅크]`. 조회 루틴은 ROMB를 `$01`로 바꾸고 `GETB`로 읽음.
  - **그리기**(`$01:EF80`에서 분기): 접두 바이트면 다음 코드를 읽고, 표에서 헤더 주소·뱅크를 얻어 `$70:00BA`를 잠시 바꾼 뒤
    1글자 그리기 루틴 `$01:EF91` 호출. 이때 R12=`A55A`(표식), R13=뱅크.
    한 줄 그리기 카운터 `$70:002E`는 바이트 수 기준이라 2바이트 글자일 때 1을 추가로 감소 (안 하면 줄 끝 글자가 중복 출력됨).
  - **1글자 그리기의 폰트 뱅크**(`$01:EFAB` `IBT R0,#$0D; ROMB` 대체): R12가 표식이면 R13을 ROMB로, 아니면 원래대로 `$0D`.
    `EF91`은 게임의 다른 곳(`$01:EC31` 등)에서도 호출되므로 표식으로 구분.
  - **폭 계산**(`$01:EDD8`에서 분기): 글자마다 맵 주소 R9를 현재 폰트(`$BA`+7) 또는 표의 페이지로, ROMB를 해당 뱅크로 설정.
    이 루틴은 R11(복귀 주소)과 R13(누적 폭)을 쓰므로 R11은 스택(R10)에 보관하고 R13은 건드리지 않음.
- GSU 파이프라인 특성: 분기·점프 직후 1바이트 명령(지연 슬롯)이 실행됨. 훅 코드는 모두 지연 슬롯에 `NOP`.
- 검증: 216개 대사를 `gsu_emu.py`로 롬의 폭 계산 루틴에 넣어 줄바꿈 결과가 이전 구조와 완전히 같음을 확인.
  모든 페이지의 글자를 넣은 시험 롬으로 Mesen 화면 출력 확인.

## 4. 그래픽 압축 (`tools/sf2_lzpy.py`)

2D 그래픽은 GSU 루틴 `$01:D9FF`가 풀어 GSU RAM에 놓고 65816이 DMA로 VRAM에 올림.
입력: `$70:006A` 뱅크, `$70:0068` **끝** 주소, `$70:002C` 출력 주소.

- 블록은 끝에서부터 거꾸로 읽음. `끝-1,끝-2` = 출력 크기, `끝-3,끝-4` = 0, 그다음 32비트 워드들(첫 워드는 자체 센티널 비트 포함).
- 비트는 워드의 LSB부터, 여러 비트 값은 MSB부터.
- 토큰: 리터럴 개수(3비트, 7이면 확장) → 리터럴 → 출력이 다 차면 종료 → 매치(길이 2~255, 거리 8/12/14/16비트).
  자세한 비트 배치는 `sf2_lzpy.py` 첫 부분 주석 참고.
- 뱅크 `$15-$19`에서 블록이 빈틈 없이 이어짐(앞 블록 끝 = 다음 블록 시작, 뱅크는 `$8000`부터).
- 블록을 가리키는 65816 코드 패턴:
  - `A9 bb 00 8F 6A 00 70 A9 lo hi 8F 68 00 70` (LDA #뱅크 / STA $6A / LDA #끝 / STA $68)
  - `JSR $D674` 또는 `JSR $D6B1` 뒤 인라인 `[lo hi 뱅크][00 00 00][플래그]`
- 제자리 삽입: 새 블록이 원래보다 작거나 같으면 같은 끝 주소에 맞춰 넣음(앞쪽 남는 공간은 읽히지 않음).
  커지면 롬 안의 빈 공간으로 옮기고 위 참조를 수정(`gfx_ko.find_refs`). 현재 `19_8A80`(조작 설정)이 `$00:FAB2-FF56`으로 이동.
  줄어든 블록의 앞쪽 남는 공간도 빈 공간 목록에 추가됨.

## 5. 그림 글씨 (`translation/gfx_ko.py`, `tools/gfx_ko.py`)

블록 이미지는 16타일 폭(128px), 4bpp 또는 2bpp 평면 타일.

| 블록 | 내용 |
|---|---|
| `19_8000-8A80` | 맵 HUD (파일럿, 실드, 아이템, 타임, 스코어, 코네리아 대미지) |
| `18_DF19-EAE9` | 파일럿 셀렉트, 충전, 실드, 스피드 |
| `18_9697-A6FF` | 아이템(상하 반전 저장), 컨트롤, 셀렉트/컨트롤 큰 글씨, 파트너 |
| `19_8A80-8EE4` | 조작 설정 (2bpp) |
| `18_BF5D-DF19` | 결과 화면 |
| `17_9B74-AA48` | 기록 화면 문장 |
| `17_8000-9B74` | EXPERT 레벨 안내 |
| `16_DDD4-E5F8` | 일시정지 메뉴 (배틀 계속, 맵으로 복귀, 카메라) |

주의점:
- 셀렉트/컨트롤 큰 글씨는 16×16 스프라이트가 타일 행 y24~31을 두 번 공유하므로 글자를 y17-23, y32-38 안에만 그려야 함.
- 일시정지 메뉴는 타일 64-73 / 80-89 / 77-79가 가로로 이어진 스프라이트.
- MISSION 설명 패널은 압축이 아닌 **8bpp 초상화 시트**(파일 `0xA0000`, 256×128, 칸 32×40) 안에 있음. `build_ko.patch_portrait_text`로 수정.

폰트: Galmuri7(7px 라벨), Galmuri9(대사·중간 글씨), Galmuri11(큰 글씨). BDF에서 직접 읽어 OS 폰트와 무관.
