# v1.1 그래픽 개선 (2026-09-20)

대사·번역 문구는 바꾸지 않고 12개 그림 글씨의 픽셀 표현을 수정했다.

## 변경 내용

- HUD 코네리아/대미지: 고정 6px 글리프를 사용해 자동 행 삭제를 없앰. '코'의 가로획 사이 간격을 보존하고 보이는 픽셀 기준으로 가운데 정렬.
- 셀렉트/컨트롤 및 기록삭제·토털·점수·재도전·타이틀·기록보기: 1px 가로 팽창을 제거해 글자 내부 공간을 유지. 9px 버튼의 외곽선은 유지.
- 일시정지 메뉴 3종: 7px 본체 + 오른쪽 아래 1px 그림자로 8px 타일 안에 장식까지 수용.
- 수정 항목은 `strict_bounds`로 최종 본체·그림자·외곽선 픽셀의 잘림을 빌드 오류로 검출.
- 스코어 '파일럿'의 공유 타일 정렬 문제는 유지. 해결에는 타일맵 분리 검토가 필요함.

HUD6 픽셀은 Galmuri7 기반 파생물이며 `fonts/OFL-Galmuri.txt`의 SIL OFL 1.1을 적용한다.

## 기존 완성 롬을 보존하는 빌드

```powershell
python tools/build_graphics.py --rom "원본 일본판.sfc" --out "out/sf2_ko_v1.1.sfc"
```

저장소의 v1.0 BPS로 기준 롬을 자동 생성한다. 기존 v1.0 롬은 `--baseline`으로 지정할 수도 있다.
원본과 기존 v1.0 입력은 SHA1로 확인한다. 크기는 1MB이며, 기존 롬의 그래픽 스트림 4개와 SNES 체크섬만 바꾼다. 대사 폰트나 코드·포인터를 재배치하지 않는다.

결과 화면 블록 앞의 빈 공간 일부에는 기존 대사 폰트가 있으므로 기본 압축으로 커진 데이터를 덮어쓰면 안 된다. `build_graphics.py`는 이 충돌을 검사하고, 필요할 때 비트 절약량을 고려하는 선택적 압축 탐색으로 같은 픽셀을 더 작게 저장한다. 압축 포맷은 동일하다. 기본 `compress()` 결과는 기존 방식 그대로다.

전체 빌드인 `build_ko.py`도 새 그림 글씨를 사용하지만 빈 공간에 폰트를 재배치할 수 있어 아래 해시와 달라진다. 아래 해시는 `build_graphics.py` 결과를 가리킨다.

| 항목 | 값 |
|---|---|
| 크기 | 1,048,576 bytes |
| SHA1 | `a398c11656ee922b0f9664c15b2968a93904468d` |
| CRC32 | `F9F6E81E` |

## 검증

- 8개 그래픽 블록 모두 수정 정의를 원본에 렌더한 결과와 일치.
- 변경된 픽셀은 지정한 12개 라벨 범위 안에만 존재.
- 그래픽 스트림 4개와 체크섬 밖의 모든 바이트는 기존 v1.0과 동일.
- 수정한 4개 블록은 로컬 GSU 인터프리터에서 원래 게임의 압축 해제 루틴 `$01:D9FF`를 실행해 복원 결과를 대조.
- 잘리는 외곽선을 넣은 검증 사례에서 `strict_bounds`가 오류를 발생시킴.
- SNES 체크섬 및 일본판→개선판, v1.0→개선판 BPS 재적용 결과 확인.
- 제작자가 개선판 인게임 확인을 완료한 뒤 v1.1 배포를 승인함 (2026-09-20).
- 자동 비교 이미지의 팔레트는 형태 확인용 임시 색상. 실기 동작 확인을 의미하지 않음.

`release/`에 v1.1 일본판용 BPS·IPS, v1.0 업그레이드 BPS, 설명서와 라이선스를 포함한 ZIP을 제공한다. v1.0 패치 파일은 빌드 재현과 이전 버전 보존을 위해 유지한다. 롬·추출 이미지·스크린샷은 배포하지 않는다.
